# PA 存储模型

PA 在 SQLite 里保存分析定义、呈现视图、报告、看板、导出票据、业务术语和最少量的使用记录。查询结果、`RenderBundle`、CSV、明细记录和只读 parquet 都不存入 SQLite。

## 各对象的身份

- Analysis 是不可变的数据问题，只保存指标、维度、筛选、时间和受控计算。
- View 是不可变的呈现选择，通过 `analysis_id` 引用 Analysis；图型与通道分配、作者的视觉偏好分开保存。
- 一个 Analysis 可以有多个 View。创建 View 不复制 Analysis，也不保存查询结果。
- Report 是可修改的业务对象，指向当前使用的 `view_id`；ReportRevision 保存历史名称和历史 View。
- Board 只引用 Report。报告改名、恢复历史版本或更换 View，都不影响看板上的引用。
- UsageLog 可以记录某次运行用到的 Analysis 和 View，但它不是定义、不是结果，也不能用来重放。

协议里的 `view_id` 指保存下来的 View；AnalysisDefinition 里结果节点的 `result_view_id` 是查询内部的标识，两者不能混用。每项业务数据只保存在一处：Analysis 定义、View 意图或 View 偏好，其他对象只保存引用。

## 写入、重放与授权

新的数据问题必须先编译并执行成功，然后在同一个事务里创建 Analysis 和它的第一个 View。修改查询定义会生成新的 Analysis；只修改呈现意图或视觉偏好会生成新的 View，不重新执行查询。MCP 重新运行已有的 Analysis 时，用当前数据执行并创建新的 View，原 Analysis 不变。

保存 Report 只是给某个 View 起名，不复制数据。改名、更换 View、归档和恢复都通过版本号做比较后写入（CAS），防止并发覆盖；修改前先保存历史版本，最多保留最近 20 个版本。所有者、引用关系和使用记录的校验由 Report 和 Board 的应用服务负责，传输层只做协议转换。

每次打开 View、Report 或 Board，都读取当前数据，按当前查看者重新授权，再编译执行。展示、导出和查看明细都通过 `view_id` 找到完整定义；客户端提交的成员、筛选条件或单元格坐标不能代替服务端的重放和校验。

`RenderBundle` 只属于一次响应，不单独保存。Report 可以缓存所有者最近一次打开时得到的布局提示，但它不属于 View，不进入版本历史，也不保证以后的数据还是同样的形态；更换 View 时必须作废。

## 生命周期

- View 依附于 Analysis。只要某个 View 被当前或历史版本的 Report 引用，它的 Analysis 就不能被清理。
- Analysis 保留 180 天，只清理过期且没有受保护 View 的记录。
- UsageLog 只保留最少量的观察字段，90 天后清理，不保存原始工具参数或查询结果。
- ExportTicket 只保存查询计划、所有者和 15 分钟有效期；下载时按当前权限重新执行。
- 归档的 Report 仍然保留，看板引用和版本历史继续有效。

数据库结构只以 `app_database.ts` 里的最终 DDL 为准。空数据库直接建立当前结构；非空数据库的结构标记（写在 SQLite `user_version` 里的 DDL 摘要）与当前不一致时，打开数据库直接报错，由部署环境重建数据库。本文不另外维护一份表结构。

## 业务术语

业务术语与模型目录分开保存，内容包括标准叫法、完整定义、可选的使用场景、其他叫法，以及关联的公开语义成员 ID。标准叫法和别名在匹配和查重时先做统一规范化，展示时保留原文。关联成员只用于目录导航，不保存物理字段、数据值、筛选条件或查询写法。管理员权限和成员可见性的校验由应用服务负责。
