# 代码与仓库内容质量标准

本标准用于每次变更完成后的仓库清理。它只定义审查方法，不复制架构、业务口径、前端形态或开源边界；这些事实源仍是 `AGENTS.md` 及对应专项规格。

## 验收标准

变更应同时满足：

- 仓库只陈述当前可用的设计、合同和使用方式。
- 同一个判断只有一个事实源，其他位置只引用它或直接删除重复内容。
- 注释只解释代码、类型和测试无法表达的当前约束或理由。
- 测试验证当前行为、公开合同或结构性边界，不将已删除的符号或实现当作永久黑名单。
- 变更不引入未使用实现、失效引用、重复配方、兼容墓碑或无对应执行者的文档。
- 受影响的引用、测试、文档和示例与代码同步，开源边界扫描和完整质量门禁通过。

## 内容判定

对本次 diff 与受影响内容逐项归类：

| 分类 | 判定 | 处理 |
| --- | --- | --- |
| KEEP | 当前仍成立，且无法由代码结构直接得出的约束、理由或公开合同 | 保留在它的唯一事实源 |
| MOVE | 内容正确，但位于错误层级或非事实源 | 移到正确位置，删除原文 |
| EXECUTABLE | 可由 schema、类型、共享常量、lint 或行为测试客观守护 | 转成可执行约束，删除重复文案 |
| DELETE | 历史过程、被否决方案、代码复述、重复定义、墓碑、过期计划、注释掉的代码或一次性取证 | 直接删除，不改写成另一段解释 |
| REVIEW | 含义不确定，或可能影响业务行为、公开 schema、指标、权限、默认口径、对外文案与授权归属 | 停止猜测，保留现状并在审查结果中上报 |

清理不得改变业务行为、公开合同、指标定义、权限或默认口径。如果变更本身就是修改这些内容，清理阶段只验证实现与已批准设计一致。

## 必须检查的内容

### 代码与配置

- 未使用的导入、导出、参数、状态、分支、类型、依赖与配置。
- 重复实现、冗余适配层、只为旧路径保留的兼容代码。
- 未执行的备选方案、提前设计的扩展点和没有当前消费方的抽象。
- 代码、配置、容器、构建脚本与 CI 之间的路径、命令、版本和入口不一致。

### 注释与文档

- 失效的符号、路径、功能、参数、界面行为和运行方式。
- 「以前」「上一版」「不再」「已删除」「为了避免某个旧问题」等方案演变叙述。
- 与代码、类型、测试名或上位规格重复的解释。
- 过期 TODO、临时记录、实测过程、一次性命令输出和可由 Git/PR 保存的背景。
- 不可验证、没有当前执行者或与仓库实际状态不一致的操作文档。

陈述当前设计时使用正向句式。「是 Y」已能完整表达时，不保留「不是 X」。只有对比外部库、语言语义、宿主限制或公开兼容边界时，才保留必要对比。

### 测试与示例

- 测试名和断言应描述当前行为，不保存被删除实现的名字。
- 优先测试输入输出、公开类型和用户可见结果；只有架构边界无法通过行为观测时才扫描源码。
- 源码扫描必须覆盖真实边界、具有反向自检，且不得将通用语法或可访问性属性列入黑名单。
- Demo 和夹具只表达当前公开能力，不承担内部数据的匿名复制或历史兼容。

### 开源边界

以 `AGENTS.md` 的公开/私有边界为唯一判据。至少手工检查本次变更中的文字、模型、夹具、示例、日志、图片和部署配置，并运行开源边界扫描。存在不确定的业务含义或授权问题时按 REVIEW 处理。

## 每次变更后的执行流程

1. 确认目标分支与变更范围，阅读完整 diff，不只阅读最后一次 commit。
2. 从变更中提取已删除或改名的符号、功能用语、路径和配置键，使用 `rg` 全仓检查受影响引用。这些搜索词只用于当次审查，不写入永久测试。
3. 阅读所有改动文件的相关上下文，检查未使用实现、失效注释、重复规则、旧测试和文档偏差。
4. 按 KEEP / MOVE / EXECUTABLE / DELETE / REVIEW 归类。直接处理高置信度的 MOVE、EXECUTABLE 和 DELETE；REVIEW 项不猜测。
5. 按影响比例运行定向测试，然后运行 `cd server && bun run check`。修改语义模型时追加 `AGENTS.md` 规定的模型回归。
6. 重新执行步骤 2 的全仓搜索，再阅读最终 diff，确认清理没有为旧实现引入新文档、新兼容层或行为变化。

审查结果必须报告：

- 已删除、移动或转成可执行约束的内容。
- 仍需人工决策的 REVIEW 项，包含文件和位置。
- 定向验证、完整门禁与开源边界扫描结果。
- 最终工作树状态，以及是否适合提交或合并。

## Agent 执行合同

当用户要求「按代码质量标准清理本次变更」时，Agent 必须完整阅读本文档、`AGENTS.md` 和受影响的专项规格，然后执行「每次变更后的执行流程」。

Agent 可直接处理不改变业务含义的高置信度清理；REVIEW 项只上报，不猜测。不通过增加注释、兼容分支或第二份规范补偿被删除内容。
