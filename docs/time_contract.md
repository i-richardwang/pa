# PA 时间合同

PA 将时间分成三个层次：用户声明要观察的业务期间，指标声明如何在时间桶上求值，服务端把两者编译为
带真实期间的结果。查询方选择时间，不选择指标的求值方式；消费方读取结果，不从指标名称或物理查询反推
时间口径。

## 1. 查询时间是用户意图

公开时间意图由 `window` 与可选的 `comparison` 组成。准确的输入形状由
[`TIME_INTENT_INPUT`](../server/src/semantic_core/time_contract.ts) 定义，本文只说明代码结构无法表达的
业务语义。

- `window` 同时表达观察期间与输出粒度。单月问题只有一个结果桶；期间问题按声明的月或年粒度形成序列。
- 相对窗口以数据源的 `actual_through` 为终点并随数据推进；带明确月份或起止月的窗口保持冻结。
- `previous_period` 是上一段等长期间，`previous_year` 是去年同月或去年同期。非等长期间只能用明确的
  自定义对照，并称为基准比较，不称为同比或环比。
- YTD 是从年初到锚点的查询窗口，不是另一类指标。去年同期通过把整个窗口回移一个日历年得到。
- 整段读数由结果的合计位提供，不是一档输出粒度。月度或年度序列也可以同时拥有服务端计算的整段读数。

公开时间意图只解析一次。基础结果、构成占比分母、总体和 Top-N 排名共享同一份业务时间坐标；下游只能
消费已经解析的坐标，不能再次解释用户输入。

## 2. `time_contract` 是指标合同

每个公开指标和运行时依赖的内部指标都必须声明：

```yaml
meta:
  time_contract:
    aggregation: sum | average | last | recompute
    window: selected | year_to_date
    grain: month # 可选
```

字段的稳定语义如下：

| 字段 | 语义 |
|---|---|
| `aggregation: sum` | 在目标业务桶内求和。 |
| `aggregation: average` | 在目标业务桶内求平均。 |
| `aggregation: last` | 取目标业务桶终点的值。 |
| `aggregation: recompute` | 聚合组件后按正式指标公式重算，不平均已经计算的比例。 |
| `window: selected` | 使用用户选择的业务桶。 |
| `window: year_to_date` | 在每个业务桶终点读取当年一月至该月的累计或成员资格结果。 |
| `grain: month` | 指标只在单月桶上有定义，连续月份必须按月返回。 |

`window: year_to_date` 与 `grain: month` 不能同时声明。正式比率从组件递归取得时间合同；组件无法形成唯一
业务期间时，语义包装配失败。

指标合同向公共目录投影为两个互不替代的字段：

| 公共字段 | 含义 |
|---|---|
| `time.value_basis` | 指标值实际覆盖业务桶里的哪一段时间。 |
| `time.constraints` | 用户可以选择哪些时间粒度和对照方式。 |

`value_basis` 有三种稳定语义：

| 基准 | 真实期间 |
|---|---|
| `bucket_end` | 业务桶最后一个月。 |
| `whole_bucket` | 整个业务桶；具体是求和、求平均还是重算比例，由指标合同决定。 |
| `year_start_to_bucket_end` | 业务桶末月所在日历年的一月至末月。 |

`constraints` 只承载选择限制：`grain: month` 限制跨月查询的输出粒度，`year_scoped` 表示整段读数不能跨
日历年，`comparison: explicit_only` 表示该时间源只接受明确的自定义对照。按月定义的指标在跨月坐标上
没有整段值时，合计位退到终点月并标记 `degraded`。

## 3. 时间来源由语义包声明

`semantic_package.yml.time_sources` 定义业务时钟及其关系。每个包必须有唯一主时钟；计划时间源可以引用
实际时间源作为实际数据边界。`calendar` 允许日历平移得到上一期和去年同期，`explicit_only` 只接受明确
期间，适用于不应按日历自动匹配的观测数据。

稀疏数据是否密化为月度状态属于语义包的数据建模策略。密化后的月份表示不晚于桶末的最近状态，批次
身份仍应作为业务维度披露。

## 4. 结果公开业务时间

直查结果中的 `view.time` 给出服务端最终采用的粒度、主期与对比期坐标，以及带业务键的时间桶。
`view.column_time_basis` 为每个指标列声明求值基准；它与时间桶共同确定每个单元格代表的真实期间。
`view.totals` 只携带实际起止月和可选的降级标记，基准继承自所属指标列。

派生结果中的搬运列继承来源指标的基准；算式列通过 `provenance` 说明来源期间。无法形成单一业务时间轴时，
结果逐列披露来源，不制造合并时间轴。

指标的物理窗口、求值形态、查询腿数量和 Cube 时间成员不属于公共协议。呈现层依据结果坐标组织时间轴和
对比系列，不按列名、指标名称或数据值猜测时间角色，也不自行对指标做算术。

## 5. 不变量

- 用户时间只在业务时间编译边界解析一次，所有执行分支共享解析结果。
- 指标求值期间由指标合同产生，并随结果交付；物理窗口不能反向定义业务期间。
- 跨事实指标先在各自事实内聚合，再按规范维度与业务时间键对齐并重算。
- 时间限制、求值基准和指标公式只由语义模型投影，MCP、前端和 Skill 不复制定义。
- 物理绑定变化时，标题、导出、记录投影与公共列身份仍必须表示同一业务含义；数值相等不能代替身份一致。
