# 正式指标架构

PA 采用“独立宽事实 + 正式指标图 + 聚合后对齐”。目标是让业务查询只面对指标、可分析维度和业务
时间，同时让每一层只承担一种计算职责。

## 分层

1. 公开 Demo 语义包发布四份独立宽事实：人员月末快照、入职事件、离职事件和部门编制计划。
   每份事实物理携带适用的时间、组织与员工属性，不在查询时连接原始行；外部语义包可以按相同合同
   增加其他独立事实。
2. Cube 模型定义事实内叶子指标、维度、访问策略和可下钻记录集。每张事实各有一个指标执行 View；
   View 只承载物理成员白名单与权限，不充当业务分类。Cube 查询只能引用一个事实来源，事实内跨行
   计算可使用 multi-stage measure。
3. 语义包声明业务指标域与规范维度构件。指标声明业务域，事实维度声明构件归属；
   指标域负责发现，维度构件负责语义身份，两者都不参与物理选路。
4. 服务启动时装配唯一的 `CanonicalSemanticModel`；能力地图、Catalog、Planner 和 Record Projection
   均从该模型投影。装配与权限合同见“Canonical model 与权限”。
5. 正式指标模型定义跨事实指标 DAG。节点引用规范指标 id，并显式声明时间合同、缺失值、零分母、
   格式、权限闭包和 Record Projection。
6. Metric Planner 把一次逻辑查询展开为最少的事实内 Cube 查询腿——一条腿即按事实来源与求值形态
   拆出的单条 Cube 查询；Metric Executor 只执行计划；
   Metric Calculator 按完整规范维度键与业务时间键 full outer 对齐聚合结果，再执行指标节点声明的
   逐行公式。
7. Application Service 把执行结果编译为分析、呈现、报告和导出；MCP 与 Web adapter 只映射协议。

## 指标与维度身份

公开指标以规范短名为语义身份。一个叶子指标只能绑定一个执行 View，并归属一个业务指标域；正式
复合指标同样声明业务域与执行宿主，但其事实依赖由指标图决定。正式复合指标只在指标模型中注册一次，
不在 Cube View、MCP 工具或报告中复制公式。Planner 只编译计划，Executor 只编排查询执行，Calculator 只对齐
聚合结果并计算模型节点；物理成员和中间结果不进入公共查询协议。

全局维度构件定义“组织与部门”“岗位与职级”等业务属性组，每个构件只有一个语义节点；事实绑定列出
该宽事实物理携带的成员。跨事实同名维度表示同一语义合同，不表示物理共享维表。名称相同的成员必须
归属同一构件，并拥有一致的业务含义、标题、类型、格式和时间语义；不一致时模型装配 fail-closed。
Planner 按规范短名把逻辑维度映射到各事实腿，所以查询能够按共同维度对齐，但不会产生原始事实 join。

## Canonical model 与权限

应用进程只装配一次完整语义模型。服务身份读取 Cube 完整 `/meta`，得到 Cube YAML 编译出的物理成员
与 View 结构；语义包提供 taxonomy、正式指标图及能力血缘。启动边界校验两侧的指标身份、维度归属、
时间锚点及执行合同，任一漂移均 fail-closed。Catalog、查询编译、翻值和记录投影共享该模型。

请求身份的 `/meta` 只提供 View 与成员可见集合，应用在 canonical model 上取交集。标题、说明、分类、
时间合同、公式和记录集合同均来自 canonical model；记录集只有在全部字段可见时才进入授权投影。
Cube `/load` 使用同一用户 security context 执行行权限，因此成员权限与行权限都由 Cube access policy
裁剪，业务语义保持单一事实源。

同一授权目录按消费者显式投影，不把某个传输协议对象当成领域模型：Web 的公共目录保留供人浏览的
维度分组与公式跳转信息；MCP 再以字段白名单投影 Agent Catalog，只交付选材、查询合同和避坑所需
语义。两者共享 canonical model 和权限裁剪；新增字段仅在对应白名单显式更新后进入该消费面。

## 查询执行

一次查询按以下顺序执行：

1. 语义编译器校验指标唯一归属、共同维度空间和用户业务时间。
2. Planner 递归展开复合指标，得到叶子指标集合。
3. 叶子按事实来源和时间求值形态分组；每组生成一条 Cube 查询。
4. Cube 在各自宽事实内完成权限、筛选与聚合。
5. Executor 对每条腿检查业务键唯一性，再做 full outer 对齐。
6. 指标图按拓扑依赖执行比例与可用性守卫；缺失分子、缺失分母、零分母和不可用批次按节点合同处理；
   声明 `result_guards.minimum_support` 的指标在结果装配时按显式支撑指标保护低支撑量单元格，
   并在结果级披露保护说明。
7. Top-N 先在声明的选择粒度上完成正式指标排名，再以选中组过滤完整展示粒度；总体与导出复用同一
   选择准备流程，不累加已算出的比率。

该链路覆盖离职率、入职率、编制达成率，以及 point/flow/PTD 在同一业务时间桶中的不同求值方式。
外部包可登记任意时间来源，并用 `comparison_policy: explicit_only` 禁止不适合日历平移的相对对照；
稀疏数据是否密化为月度状态快照属于包的数据建模策略，不产生核心数据类型。
固定指标不使用用户派生 AST；派生 AST 只服务于同比、环比等用户本次查询明确声明的结果级异窗计算。

## 记录投影

名单和明细不是维度，也不是公共 Entity。可下钻指标通过 `underlying_records` 绑定一种记录集：在职
快照、入职事件或离职事件。率指标绑定分子记录。每种记录集拥有自己的字段投影，
因此离职记录可以包含离职日期与原因，而在职记录不需要伪造这些字段。个体行只经受控 Record
Projection Service 交付，不进入模型可见结果或持久化分析。

## 红线

- 不使用 shared dimension、Cube Multi-fact 或原始事实实时 join。
- 不把另一张事实的数据复制进分母表来规避正式指标计算。
- 不在 MCP adapter、前端、报告或 skill 中重定义指标公式。
- 不让 MCP 直接序列化 Web 目录或内部 canonical model；Agent 能力面必须经过独立白名单投影。
- 不按字段同名猜测对齐；只有通过规范维度合同的成员才能跨事实使用。
- 不平均已计算的率，不把缺失分母解释为零，不在腿内重复键上隐式聚合。

正式图不只承载率。依赖另一个事实才能判断“0 还是未知”的计数也必须建模为节点。例如某事件计数
可以以资格事实的批次可用性为守卫：资格批次存在而事件缺行时返回 0，批次不可用时返回空值。
下游比率直接依赖这一正式计数，聚合结果与记录投影因此共享同一口径。
