# 正式指标架构

PA 采用“独立宽事实 + 正式指标图 + 聚合后对齐”。业务查询只面对规范指标、可分析维度和业务时间；
物理事实、执行成员和中间结果不进入公共协议。

## 事实、指标与维度

- 一张宽事实只承载自己的数据，不在查询时连接原始事实行。事实内聚合由 Cube 完成。
- 叶子指标绑定一个执行 View；跨事实指标只在版本化指标图中注册一次，由单事实查询腿聚合后计算。
- 指标域用于发现，维度构件用于语义身份，都不参与物理选路。
- 跨事实同名维度必须具有相同的业务含义、类型、格式和时间语义。Planner 只按通过合同校验的规范
  维度键对齐结果，不按字段同名推断关系。
- 复合指标的公式、时间合同、缺失值、零分母、权限闭包和记录投影属于指标模型；adapter、前端、
  报告和 Skill 不得复制这些规则。

## Canonical model 与权限

服务启动时把 Cube `/meta` 与语义包装配为唯一的 `CanonicalSemanticModel`。Catalog、能力地图、查询编译、
翻值和记录投影都从该模型投影；重复来源、未知分类、循环依赖、缺失锚点或合同不一致必须 fail-closed。

请求身份的 `/meta` 只提供 View 与成员的可见集合，应用在 canonical model 上取交集；Cube `/load` 使用
同一用户 security context 执行行权限。业务语义始终来自 canonical model，权限只裁剪可见成员和数据行。
记录集只有在全部字段可见时才进入授权投影。

Web Catalog 与 Agent Catalog 是同一模型面向不同消费者的显式白名单投影。Web 可以保留浏览和跳转信息；
Agent Catalog 只交付选材、查询合同和避坑所需语义。任何新增字段都必须显式进入相应投影。

公开错误使用统一的领域分类。MCP 工具返回 `isError: true` 与稳定的结构化错误；Web API 保留同一
`code` 和 `details`。未知异常的诊断只写服务端日志。

## 公共能力与执行边界

Catalog 必须给每个指标交付正向查询能力：可用维度、层级、最少分组数、时间选择限制和报告计算能力。
指标值实际代表的期间由 `time.value_basis` 表达；用户可以选择什么时间由 `time.constraints` 表达，二者
不能互相代替。

Query Feasibility Evaluator 只消费公开能力，统一判断成员引用、共同维度、时间选择、对照与报告计算。
Console 用它在编辑时解释不可用项，语义编译器在规划前复验。依赖实际返回规模的容量限制只能在执行后
判定，并返回带运行证据的 `limit_exceeded`。

查询执行必须满足以下不变量：

- 每条物理查询腿只访问一个事实来源；复合指标按依赖图展开，聚合后再按完整规范键对齐。
- 业务时间只解析一次。基础结果、grouping set、整窗读数和记录投影必须继承同一时间签名。
- grouping-set 广播只允许同一正式指标在细、粗分组集之间进行；粗分组集必须是细分组集的真子集，
  两侧键各自唯一，筛选血缘和业务时间完全一致。
- 总体与 Top-N 由服务端按正式指标重算，不累计可见行，不平均已计算的率。
- 缺失分子、缺失分母、零分母、批次可用性和最小支撑量按指标节点合同处理，不在呈现层补规则。
- 物理 Planner 与 Executor 只验证编译产物的不变量，不重新解释用户意图。

## 记录投影

名单和明细不是公共维度或 Entity。可下钻指标绑定记录集；率指标绑定分子记录。每种记录集独立声明
字段、实体键和稳定排序。个体行只能经受控 Record Projection Service 交付，不进入聚合结果或持久化分析。

## 红线

- 不使用 shared dimension、Cube Multi-fact 或原始事实实时 join。
- 不复制另一事实的数据来规避正式指标计算。
- 不在 adapter、前端、报告或 Skill 中重定义指标公式。
- 不让 MCP 直接序列化 Web Catalog 或内部 canonical model。
- 不按字段同名猜测对齐，不平均已计算的率，不把缺失分母解释为零。
- 不把 grouping-set 广播塞进派生视图 join；派生视图只处理同键一对一的异窗结果计算。
