# 正式指标架构

PA 的做法是：每张宽事实表各自独立；跨表的指标登记在一张正式指标依赖图里；各表分别汇总后，再对齐结果。"正式指标"指语义包里登记过、对外公开的指标。业务查询只接触正式指标、可分析的维度和业务时间；物理事实表、执行用的内部成员和中间结果都不出现在公共协议里。

## 事实、指标与维度

- 一张宽事实表只存自己的数据，查询时不把不同事实表的原始行连接起来，也不使用 Cube 的共享维度（shared dimension）或 Multi-fact 查询；不把一张表的数据复制到另一张表来绕过正式指标计算。单张事实表内的汇总由 Cube 完成。
- 基础指标（叶子指标）绑定一个执行 View。跨事实表的指标只在版本化的指标依赖图里登记一次，执行时拆成若干单表子查询，各自汇总后再计算。
- 指标域用于目录浏览，维度分组用于确定维度的语义身份，两者都不影响查询走哪张物理表。
- 不同事实表里的同名维度必须在业务含义、类型、格式和时间语义上完全一致。Planner 只按通过校验的标准维度键对齐结果，不因为字段同名就认为它们是同一个维度。
- 复合指标的公式、时间合同、缺失值和零分母处理、权限要求以及明细记录，都属于指标模型；adapter、前端、报告和 Skill 不得另写一份这些规则。

## 统一语义模型与权限

服务启动时，把 Cube 的 `/meta` 和语义包合并成唯一的 `CanonicalSemanticModel`。指标目录、能力地图、查询编译、维度候选值查询和明细记录都从这个模型生成。遇到来源重复、分类未登记、循环依赖、缺少时间锚点或定义不一致时，直接拒绝加载。

每个请求用当前身份调用 `/meta`，只用来获取该身份能看到哪些 View 和成员，应用再拿它与统一模型取交集；Cube `/load` 使用同一个用户安全上下文执行行级权限。业务含义始终来自统一模型，权限只决定能看到哪些成员和哪些数据行。一个记录集只有在全部字段都可见时，才对该用户开放。

Web 目录和 Agent 目录是同一个模型面向不同使用者的两份输出，每份都只包含白名单里明确列出的字段。Web 目录可以带浏览和跳转所需的信息；Agent 目录只提供选择指标、构造查询和避免常见错误所需的内容。新增字段必须明确加入对应的白名单；MCP 不直接输出 Web 目录或内部统一模型。

对外的错误使用统一的分类。MCP 工具返回 `isError: true` 和稳定的结构化错误；Web API 返回相同的 `code` 和 `details`。未预期异常的诊断信息只写入服务端日志。

## 查询能力与执行规则

目录必须为每个指标说明它支持哪些查询：可用的维度和层级、最少分组数、时间选择的限制，以及报告里可用的计算。指标值实际覆盖哪段期间，由 `time.value_basis` 说明；用户能选择什么时间，由 `time.constraints` 说明，两者不能互相代替。

Query Feasibility Evaluator 只根据公开的查询能力，统一检查成员引用、共同维度、时间选择、对照期和报告计算是否可行。控制台在编辑时用它说明哪些选项不可用，语义编译器在生成执行计划前再检查一次。取决于实际返回数据量的上限只能在执行之后判断，超出时返回带实际数据的 `limit_exceeded`。

查询执行必须满足以下条件：

- 每条物理子查询只访问一个事实来源。复合指标按依赖图展开，各部分汇总后，再按完整的标准维度键对齐。
- 业务时间只解析一次。基础结果、分组集合（grouping set）、整段合计和明细记录都使用同一份时间坐标。
- 同一个正式指标可以把粗粒度分组的结果填回到细粒度分组的每一行上（例如用部门总数作为各小组占比的分母）。这要求：粗粒度分组的维度必须是细粒度分组维度的真子集，两侧的键各自唯一，并且两侧的筛选来源和业务时间完全相同。派生视图不做这种填充，只用于键完全相同、一一对应的不同期间结果之间的计算。
- 总计和 Top-N 由服务端按正式指标重新计算，不把可见行加起来，也不对已经算好的比率求平均。
- 分子缺失、分母缺失、分母为零、数据批次是否可用以及最小样本量，都按指标节点自己的定义处理，前端不另加规则。
- 物理 Planner 和 Executor 只检查编译产物是否满足上述条件，不重新解释用户的查询意图。

## 明细记录

名单和明细不是公共维度，也不是实体（Entity）。可以查看明细的指标绑定一个记录集；比率指标绑定分子对应的记录。每种记录集各自声明字段、实体键和稳定的排序方式。逐人数据只能通过受控的 Record Projection Service 返回，不会出现在汇总结果里，也不会随分析一起保存。

## 跨期组合表

组合表以包中声明的稳定实体维度对齐各列的汇总结果。默认行集合为可用列的实体键并集，也可以指定某列的实体集合为基准。显示名称由基准列或最先提供该实体的列确定。不同键分别展示，同一键可跨期合行，缺键行不参与对齐，单列内重复键报错。不支持所选实体粒度的指标列留空。已授权且同粒度的指标列独立执行各自的正式聚合及样本保护，缺值留空，零保留。
