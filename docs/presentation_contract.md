# PA 呈现契约

查询结果怎么变成一份可读的形态，由**语义呈现意图 + 作者视觉设置 + 确定性编译**答完。
Agent 与编辑器都可以声明语义呈现意图；只有人类作者面可以声明视觉设置。服务端负责把两者合成
私有物理呈现，并执行数据完整性守卫。**服务端不反向替声明方改选图型**——声明无法忠实成立时
明确失败或退回表格，不静默改写。

指标怎么算归 `metric_architecture.md`，时间怎么解析归 `time_contract.md`，长什么样归 `ui_spec.md`；
本文只管这三者之间的那一层：**声明什么、保证什么、什么时候拒绝**。

## 1. 三层合同只在服务端汇合

| 合同 | 负责什么 | 对 Agent 可见 |
|---|---|---|
| `analysis` | 指标、维度、筛选、时间、受控计算 | 是 |
| `view`（`ViewIntent`） | 图型与数据通道：分类、主系列、拆分、堆叠、表格列轴 | 是 |
| `view_preferences`（`ViewPreferences`） | 颜色、系列线/柱覆盖、左右轴、数值标签、表格热力色阶 | 否，仅人类作者面 |

`ExecutionPlan` 与物理 `PresentationSpec` 都是服务端私有编译产物，不持久化为对外事实，也不进入
MCP schema。不可变 Analysis 只保存 AnalysisDefinition；不可变 View 通过 `analysis_id` 引用它，并分别保存
ViewIntent 与 ViewPreferences。MCP 创建或重新呈现 View 时每次都使用产品默认视觉设置。报告通过一个
`view_id` 引用完整合同。

这里的表格 `columns` 只决定交叉表行/列轴的矩阵结构；普通表格列顺序由结果合同确定。

## 2. 声明与可忠实编译的结果结构

| 显式声明 | 可忠实编译的结果结构 |
|---|---|
| KPI | 单行纯度量 |
| 折线 | 纯时间或时间 × 少量分类（量与率混合时柱线双轴） |
| 柱状图 | 单分类或双分类的有限类别（量与率混合时柱线双轴） |
| 饼图 | 单一计数指标 × 少量互斥分类 |
| 表格 | 任意结果；`ViewIntent.columns` 按声明顺序生成多层交叉表；`ViewPreferences.table_shading` 让指标格按值铺热力底色 |
| 声明或矩阵不成立 | 明确失败原因；不得静默改写布局 |

**表格始终是兜底形态**：任何图形声明不成立都可以回到忠实表格，反过来不成立。

## 3. 三种阈值，只有一种会拒绝

- **感知极限**（系列数、切片数）：超出时让声明图表回到忠实表格。
- **图形总览预算**（自然高度）：同上。
- **表格渲染资源上限**：这是唯一会**明确拒绝**的一档。

**任何阈值都不裁剪数据。** 图形阈值只改形态，资源上限只拒绝，二者都不得悄悄少给行。

## 4. 列轴是一等契约

Agent 与编辑器可在 `ViewIntent` 声明**有序列轴**：`time` 表示当前查询的逻辑时间桶，`metrics` 表示指标轴，
其他值必须是本次查询的业务分组维度；未进入列轴的业务维度自动留在行轴。

- 指标与时间同在列轴时确定性默认是 `[metrics, time]`；显式 `[time, metrics]` 才交换。
- 未声明 `columns` 时：年度/月度分类结果默认时间在列，纯月度无分类结果默认月份在行。
- **默认只在规格归一边界生成一次**，运行时不根据分类基数或结果行数偷换行列方向。
- 显示总体时业务维度不可进列轴（时间与指标仍可调序）；开启总体会**原子清除**业务维度列轴
  而保留仍合法的轴。

列角色由结果自带的 `column_roles` 给定，呈现层不猜（契约见 `time_contract.md` §4）。

## 5. 交叉表用表头路径，不维护第二份分组结构

每个叶子列只携带一条 `headerPath`，渲染层从相邻路径前缀推出跨行跨列、分组边界与表头总高度。
路径节点以**稳定结构键**合并，**不按展示标题相等**——两个指标标题偶然同名时仍是两组。

列数不改变用户声明，宽表由横向滚动承载。同一行列坐标出现多行属于无法忠实成矩阵，
必须返回**结构化失败原因**；原始长表可作为明确标注的兜底数据，但不得声称声明布局已生效。

## 6. 热力着色是人类作者视觉设置

`view_preferences.table_shading` 只允许配合 `type=table`：一个色阶（十六进制单色按深浅，或双向色阶名按冷暖）、可选翻转、
阈值覆盖与是否印数。刻度在编译期按**每个指标各自**的数值极值确定（中点取两端中点），同一指标横跨
交叉表多列共用一把刻度，不同指标不共用深浅；总体带是表格 chrome，不参与刻度也不着色。声明的
阈值逐项覆盖缺省；自动端点同时包住数据域与显式停点，保证色阶有序。渲染层只做值到色的映射与字色对比选择，不因着色改变任何数字。

## 7. 数值标签是人类作者的图级设置

`view_preferences.value_labels` 只允许配合 `type=line/bar`，两档：`main`=仅第一主系列、`all`=全部系列（含拆分系列）。
拆分系列没有「主系列」，`main` 与 `group_by` 互斥。标签格式与 tooltip 同源（率带单位、位数随列声明）；
逐点空间不足时渲染层按步距挑桶印数并恒印末点，声明本身不变。标签的场地余量留在**框内**值轴末端（纵向一行字高、
横向按最宽格式化标签实测），场地框不因标签开关移动；堆叠段的标签进段内。排行版式的值恒以独立一列
印出，不受本声明影响。

## 8. 聚合数只有一个来源

**呈现层禁止对指标做任何算术。**

- **总体**（去掉业务分组重算）与**整窗读数**（把整段时间合成一个数）都由服务端独立求得；
  呈现层只摆放与格式化。
- **禁止对当前可见行求和**凑一个总数：率不可加，行还可能被 Top-N 与交付上限截断。
- **整窗读数只随指标卡形态下发**（`presentation.totals`）：它的口径是筛选后的全量总体、
  不含分组选择，与画面上按分组铺开的数不同源。图与表的呈现块因此不带这份数据——
  版面上不出现第二个口径的读数，也就无从读串。
- **整窗读数的覆盖期间写实**：不能整窗合并的指标（按月定义、年初归零）在供给侧已退到期间终点
  求值，注脚因此可能短于所选窗口——「年初至今」不得写成「全年」。
- 差值列同样只由服务端给出（算术见 `time_contract.md` §4）；它没有单一来源行，不参与下钻。
- **格式与小数位是指标口径的一部分**：由模型成员声明（`format`、`meta.decimals`），随列进载荷
  （`column_formats`、`column_decimals`），呈现层照读；全站默认一位小数，其他位数通过成员元数据声明。
  呈现层不设读者可调的位数，统一采用全局策略，不提供逐指标的位数设置。

## 9. 记录可点性来自绑定，不来自数值

能否查看构成记录只取决于该指标有无记录集绑定（`meta.underlying_records`，见
`metric_architecture.md`），**与格里的值无关**；零值同样开放，空记录集也是诚实结果。
拿值做门槛会让同一列的数字一半可点一半不可点，可点性因此无从学会。

记录投影按 `view.time.buckets` 定位业务范围，服务端以当前查看者权限重放聚合规格并验证完整
格点坐标，**不信任客户端拼装的成员或过滤条件**。

## 10. 红线

- 不在呈现层做任何指标算术，包括对可见行求和、平均已算出的率、把缺失解释为零。
- 不因阈值裁剪数据；不把「拒绝」和「降级」混为一谈。
- 不静默改写用户声明的布局方向，也不静默退回长表。
- 不按展示标题合并交叉表分组节点。
- 不用数值有无决定记录可点性。
- 不把人类视觉设置加入 MCP schema，也不让 MCP 更新时暗中继承不可见视觉状态。
